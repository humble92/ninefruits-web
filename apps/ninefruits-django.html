Ninefruits for Django

The same student information system, rebuilt on Django. Behavior and the database schema follow the Laravel edition, so an installation can move from one to the other with ordinary PostgreSQL tools.

code View source Laravel edition

Purpose

Offer the campus the same academic system on a Python stack, without a second database design. Staff still work in an admin panel. Students, instructors, and applicants still use a portal. Korean, English, Chinese, and Lao stay in the product.

Technology stack

Python 3.14 Django 6.1 django-unfold HTMX Alpine.js Tailwind CSS PostgreSQL 18 Redis Celery Gotenberg django-allauth Django REST framework

django-unfold styles the admin panel. The portal is Django templates with HTMX, Alpine.js, and Tailwind. Celery runs the queue. django-allauth covers sign-in, two-factor authentication, and SSO. Dependencies are locked with uv.

Features

sync_alt

A faithful port

Django migrations replay the Laravel schema. The two databases are compared object by object, so a campus can change stacks without redesigning its data.

school

The full academic year

Admissions, student records, curriculum, registration, grades, course evaluation, certificates, exams, attendance, graduation review, and reports. The scope matches the Laravel edition.

api

API and sign-in

Integrations use a REST API under /api/v1/, with OpenAPI docs. Sign-in supports two-factor authentication, OpenID Connect SSO, and a student number.

lock

Access and audit

Roles and org scopes, a hash-chained activity audit, row-level security, and encrypted personal data. LMS links, event sync, and a nightly reconciliation sit on the same base.
